# Тестовый Dmailio

Адрес: **https://test.dmailio.ru**. DNS: запись A `test` → `31.77.143.213`.

## Изоляция

- Checkout: `/opt/dmailio-test`, ветка публикации `test`.
- Compose project: `dmailio-test`; порт только `127.0.0.1:9101`.
- Отдельный том `dmailio-test_outreach-data`, новая пустая SQLite.
- Новый ключ и пароль в `/etc/dmailio-test/outreach.env` (права 600).
- Не копировать production `.env`, базу, ящики, контакты и запущенные кампании.
- Подключать только тестовые почтовые ящики. Отправка реальная после явного запуска: отдельного режима запрета всех отправок сейчас нет.
- Ограничение контейнера: 512 MiB / 0.5 CPU, ротация логов. Во время Docker build проверять свободную память и диск хоста.

Текущий compose запускает существующий outreach. Маркетинговые редакторы и рассылки появятся после реализации задач №15–32. В №16 добавить отдельные PostgreSQL/listmonk сервисы и секреты этого стенда: production DB/транспорт не использовать.

## Первый запуск (сервер)

После подготовки checkout создать каталог `/etc/dmailio-test` с правами 700,
а файл `outreach.env` с правами 600. Значения `DMAILIO_KEY` — новые случайные
32 байта в hex, `DMAILIO_PASSWORD` — новый случайный пароль длиной от 16 символов.
Секреты в Git не сохранять.

```sh
cd /opt/dmailio-test
docker compose -f deploy/test/compose.yaml config --quiet
docker compose -f deploy/test/compose.yaml up -d --build
curl --fail http://127.0.0.1:9101/healthz
```

Установить `nginx.conf` как отдельный virtual host, выполнить `nginx -t`,
затем reload. После распространения DNS выпустить сертификат Certbot,
включить HTTPS redirect и проверить `/healthz`, вход и отсутствие рабочих данных.
До HTTPS вход в браузере не проверять: cookie приложения Secure.

## Публикация очередной задачи

1. Тесты задачи, ревью и merge PR в `Unisender`.
2. Продвинуть `test` fast-forward до выбранного проверенного SHA `Unisender`;
   push сам по себе ничего на сервере не разворачивает.
3. Проверить чистоту checkout `/opt/dmailio-test`, fetch `origin test`,
   зафиксировать предыдущий SHA/образ и резервную копию тестовых данных.
4. Обновить checkout до выбранного SHA `origin/test`, выполнить команды compose
   выше и проверить health, вход, сценарии задачи в браузере, production health.
5. Зафиксировать SHA, результаты и ограничения в issue. При сбое восстановить
   прежний образ и совместимую копию тестовой базы; не откатывать миграции вслепую.

Автоматического деплоя нет. Проверять стенд после каждой задачи; №31 остаётся
финальной проверкой с настоящими провайдерами, №32 — выпуском в production.
