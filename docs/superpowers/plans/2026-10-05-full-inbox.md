# Full inbox implementation plan

Goal: implement Issue #6 using the existing single-team authenticated service and existing SMTP/IMAP accounts. No additional computer or mail hosting is required.

Architecture: additive full-inbox storage alongside campaign messages, with one background IMAP sync feeding both. Canonical received messages are independent of leads. Remote folder locations are separate from messages. Existing campaign response processing remains authoritative and is invoked once per canonical incoming message.

Spec: https://github.com/perchik08/dmailio/issues/6 (user requested implementation).

Constraints: Node >=24; same SQLite database and authentication; bounded MIME/attachments and pagination; no plaintext credentials in API; no campaign counting for ordinary/warmup email; no implicit movement from spam; no automatic retry after unknown SMTP delivery. Existing accounts start full capture at rollout because original connection date was not saved. New accounts start at verification. Incoming internalDate before this baseline must be skipped even in newly discovered folders or UIDVALIDITY reset. Timestamp limitations of IMAP providers must be documented. Live verification at two providers requires accessible test accounts and is an external acceptance step.

## Interfaces

`store.fullInbox` is an instance of `FullInboxStore` in `outreach/full-inbox-store.mjs` constructed with the existing Store. It owns additive full-inbox tables and uses Store transaction, mailbox(), insertMessage(), available(), rendered().

- `capture(mailboxId, inbound, now)` -> `{id, fresh}`; incoming metadata: `remoteId`, `folder`, `validity`, `uid`, `identity` (SHA256 bounded MIME+size+internalDate or provider stable ID), `messageId`, `references`, `from`, `to` array of strings, `cc`, `replyTo`, `subject`, `text`, `html`, `internalDate` ms, `flags` string[], `type`, `attachments` array `{name,type,data:Buffer}`. Dedup must never use Message-ID alone. Locations are keyed mailbox/folder/validity/uid. `annotate(id, legacyMessage)` links campaign/lead and warmup classification without reprocessing events.
- `list(filters)` -> `{items,total,page,pageSize,folders,warnings}`. filters mailboxId/folder/campaign/kind/search/page/pageSize/view (inbox/sent/drafts). item fields id,mailboxId,mailboxEmail,from,subject,created,folders:string[],kind,campaignId,read,starred,direction,status,attachments:number.
- `get(id)` -> item + text,html(safe),to:string[],cc:string[],replyTo:string[],messageId,locations:[{folder,validity,uid}],attachments:[{id,name,type,size}]. `attachment(id)` -> `{name,type,data}`; `setLocalFlags(id,{read?,starred?})`; `relocate(id,oldFolder,newFolder)` if remote operation succeeds.
- `saveDraft(input)` -> `{id,...}`; `drafts()`; `deleteDraft(id)`; `reserveOutgoing(input,now)` -> existing messages row (`kind:mail`, frozen signature, stable Message-ID), idempotent by input.requestId (required). Input mailboxId,to:string[],cc,bcc,subject,body,format,attachments:[{name,type,data:base64}],replyToId,replyAll,forwardId,draftId. Validate recipients, quotas, no CRLF headers, attachment totals<=8MB and count<=20, text<=200k. Read replies/forwards from stored IDs and use explicit sender. Prevent concurrent duplicate sends and do not resurrect sent/unknown requests. `outgoing(messageId)` returns MIME recipients/attachments metadata. `recordSentCopy(messageId,error)` exposes copy failure separately from SMTP accepted status.

`gateway.sync` delegates full-folder sync for real mailbox IDs, retaining old sync for tests/legacy cursors where appropriate. New module `outreach/full-inbox-sync.mjs` implements `syncFullInbox(gateway,m,onMessage)`; returns cursor `{validity,uid,caughtUp,since,folders,errors}`. Per-folder cursors and baseline persisted in m.cursor. `verify` initializes folder baselines. Iterate all selectable folders; exclude Sent/Drafts for received mail. Parse bounded MIME and attachments. Include Spam/Trash/Archive/AllMail/custom. Check flags and detect removed locations. No automatic moves. At most 200 messages per folder per cycle; finite folder batch/fair resume for huge accounts. Catch per-folder failures and report them while continuing others. Source hash and internalDate dedup, provider X-GM-MSGID if available. Existing warmup placement scanner stays independent.

`gateway.updateFullMessage(m,locations,action)` applies seen/starred/archive/trash/spam via IMAP and returns metadata; validate UIDVALIDITY before action. `gateway.send` routes kind:mail through `sendFullMessage(gateway,m,message)` in sync module: MIME includes frozen attachments and signatures. Append same MIME once to provider Sent after SMTP acceptance; copy failure is exposed separately, never retry SMTP. TLS enforced by existing transports.

## Local implementation result

Implemented additive SQLite storage, folder synchronization, authenticated APIs, shared SMTP quota and mail UI. Independent review findings were repaired with regressions: concurrent arrival during initial folder scan, self-BCC deliveries, bounded remote FETCH ranges, archive source selection, APPEND false, partial SMTP rejection warnings, sent replies and received type filters. All 139 tests pass, including existing campaign/warmup behavior; formatting and diff checks pass. Browser smoke on a disposable in-memory fixture verified login, unrelated Spam message with HTML/attachment, reply-all, draft save/resume and mock send into Sent; no browser errors. No actual provider email was sent during this check.

Remaining acceptance: two real SMTP/IMAP providers, folder moves/flags and Sent behavior under provider-specific policies, Docker build and server deployment. No historical import. Large existing folders are traversed in bounded background batches; initial catch-up can delay automated campaigns while the worker waits for healthy full sync. OAuth and multi-organization isolation remain outside this issue.
