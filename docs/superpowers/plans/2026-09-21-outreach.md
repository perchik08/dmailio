# Dmailio outreach implementation plan

Goal: implement the single-team outreach workflow approved after the Trigga audit: mailboxes, CSV variables, sequences, scheduling, replies, analytics and opt-in internal warmup.

Spec: ../../../../trigga-audit/report.md (local audit); durable scope is reproduced below.

Architecture: an independently deployable Node 24 outreach service alongside listmonk. SQLite WAL stores campaign-specific contacts, immutable sent messages, queue state, mailbox credentials encrypted with AES-256-GCM, and inbound message cursors. SMTP/IMAP adapters use maintained libraries. A Russian web interface exposes the real persisted API. Existing listmonk newsletter functionality remains available as a separate service.

Global constraints: no live email without explicit campaign/warmup start; one team per instance; session authentication and same-origin writes; SMTP and IMAP TLS verification enabled; secrets never returned; uncertain delivery requires operator reconciliation instead of automatic retry; warmup restricted to opted-in connected mailboxes and excluded from campaign analytics. No claim of delivery improvement. No billing or multitenant isolation in this release.

## Interfaces

core.mjs exports parseContacts(csv), render(template, fields, sender), inferSteps(headers), validateSchedule(schedule), inWindow(date,schedule).
store.mjs exports Store(path,key), responsible for all durable state and reservations.
mail.mjs exports MailGateway with verify(mailbox), send(mailbox,message), sync(mailbox,onMessage).
worker.mjs exports Worker(store,gateway) and tick(now); serial tick prevents overlapping work in a process, DB reservations protect concurrent workers. Mailbox sync precedes automated sends; failed sync defers sending.
server.mjs exports createApp(options); no listener or worker starts on import. public/app.js uses only authenticated API endpoints.

## Review focus

Untrusted CSV/form data must remain inert in templates and HTML. Duplicate imports and ambiguous SMTP outcomes must not generate duplicate messages. Replies/opt-outs must stop queued followups. Quotas must apply across campaigns and manual/warmup sends. Date windows must follow IANA timezone and weekdays, including DST. No warmup outside the consenting pool.
