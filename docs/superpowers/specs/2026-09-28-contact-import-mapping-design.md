# Спецификация: общий мастер импорта контактов и сопоставления колонок

Дата: 2026-09-28  
Связанные задачи: [#3 — импорт Excel](https://github.com/perchik08/dmailio/issues/3), [#8 — сопоставление полей и контроль дублей](https://github.com/perchik08/dmailio/issues/8)

## Цель

Позволить загрузить CSV или `.xlsx` без приведения таблицы к шаблону Dmailio, сопоставить её колонки с полями контакта, пользовательскими переменными и шагами цепочки, проверить результат и только затем импортировать контакты в черновик кампании. Значения сопоставленных полей должны подставляться в темы и письма через переменные, например `{{Компания}}`.

Сценарий основан на показанном пользователем импорте Trigga: строка для каждой колонки, выбранное назначение и примеры исходных значений; среди назначений есть «Не импортировать».

## Объём

- Один мастер для CSV и `.xlsx`; CSV остаётся поддержан.
- Для книги Excel с несколькими листами пользователь выбирает ровно один лист. Разные листы не объединяются.
- Любые допустимые заголовки и порядок колонок. Назначение Email выбирается в мастере, а не определяется обязательным буквальным заголовком `email`.
- Стандартные поля: Email, имя, фамилия, отчество, полное имя, телефон, должность, отдел, компания, сайт, город и страна.
- Пользовательские переменные с редактируемым понятным названием, а также явный пропуск ненужной колонки.
- Отдельные явные назначения для темы цепочки и персонального текста писем от 1 до 20.
- Предпросмотр нормализованных контактов, ошибок, дубликатов и пропуска колонок до изменения кампании.
- Синтаксическая проверка адресов обязательна и выполняется локально существующей функцией `email()` в Dmailio: обрезаются внешние пробелы, адрес приводится к нижнему регистру, отсекаются запрещённые символы, проверяются допустимая длина (до 254 символов) и базовая структура `имя@домен.домен`. Внешний сервис не вызывается; существование ящика, MX/DNS домена и возможность доставки этим этапом не подтверждаются.

## Пользовательский поток

1. В черновике кампании пользователь выбирает CSV или `.xlsx`. Размер файла ограничен 10 МБ; импорт — до 10 000 строк контактов. `.xls` отклоняется с подсказкой сохранить книгу как `.xlsx`.
2. Для Excel показывается выбор листа, если листов несколько. Для полностью пустого листа показать уведомление: «Лист пустой — в нём нет данных. Выберите другой лист или добавьте данные в таблицу и загрузите файл снова.» Если в листе есть заголовки, но нет ни одной строки контактов, показать: «На листе нет строк с контактами. Добавьте данные или выберите другой лист.» Предпросмотр не создаёт и не изменяет кампанию.
3. Мастер показывает все столбцы выбранной таблицы. Каждая строка содержит исходный заголовок, несколько непустых примеров, выпадающий список назначения и состояние, будет ли колонка импортирована.
4. Мастер предлагает очевидные соответствия по заголовкам (например, «Почта» → Email, «Компания» → Компания), но пользователь может изменить каждое. Для неизвестной колонки можно создать пользовательскую переменную или выбрать «Не импортировать».
5. Пользователь должен назначить ровно одну колонку Email. Одно стандартное поле нельзя назначить двум исходным колонкам одновременно без разрешения конфликта; пользователь выбирает одну колонку для поля либо назначает вторую пользовательским полем/пропускает её.
6. Одинаковые исходные заголовки различаются стабильным идентификатором позиции и видимым номером колонки. Например, повторяющиеся «Письмо 1» остаются двумя самостоятельными строками сопоставления с разными примерами; значения не теряются и не перезаписывают друг друга.
7. Назначения темы и писем явно видны перед подтверждением. Колонки писем можно сопоставить шагам 1–20 вне зависимости от исходного названия. Если в кампании уже есть цепочка, мастер не заменяет её молча: пользователю показывается существующая цепочка и предлагается сохранить её или явно подтвердить замену до импорта.
8. Предпросмотр показывает число импортируемых контактов, примеры итоговых полей и переменных, назначенные шаги писем, строки с ошибками, внутренние дубли и дубли уже в этой кампании с причиной каждого исключения. Переключатель пропуска уже существующих в текущей кампании контактов включён по умолчанию. Отключение пропуска не позволяет создать дубликат внутри кампании.
9. Изменение любого назначения пересчитывает предпросмотр. Возврат на шаг сопоставления сохраняет сделанные назначения.
10. Подтверждение сохраняет ровно тот результат, который показан в предпросмотре. Если есть ошибки, они перечисляются с исходными номерами строк, а импорт либо сохраняет все допустимые контакты, либо не сохраняет ни одного — частичный импорт запрещён.

## Формат данных и границы компонентов

Чтение файлов отделяется от сопоставления и проверки контактов. CSV- и XLSX-ридеры возвращают одну общую структуру таблицы:

```text
ParsedTable {
  format: "csv" | "xlsx",
  sheets: [{ id, name }],
  selectedSheetId,
  columns: [{ id, position, header, samples: string[] }],
  rows: [{ sourceRow, values: string[] }]
}
```

`column.id` уникален внутри таблицы и основан на позиции, а не на тексте заголовка. `sourceRow` сохраняет строку исходного файла для диагностики. Значения Excel читаются как отображаемый текст; сервер не исполняет формулы, макросы или активное содержимое. Используется сохранённое в книге отображаемое значение, если оно доступно.

Сопоставление передаётся отдельно от содержимого:

```text
ColumnMapping[] = {
  columnId,
  target: "email" | стандартное поле | "custom" | "sequence_subject"
          | { kind: "sequence_step", step: 1..20 } | "skip",
  variableName? // только для пользовательского поля
}
```

Каждый столбец получает ровно одно назначение. Стандартные поля приводятся к принятому приложением набору имён переменных; пользовательское поле получает уникальное имя переменной, пригодное для `{{...}}`. Имена проверяются на пустые значения, конфликты, повторения и системные переменные отправителя. Сопоставление стандартных полей должно оставлять совместимость с ранее импортированными CSV и существующими шаблонами, в том числе `{{name}}` и `{{company}}`.

Для дублей внутри файла и кампании используется нормализованный email. Уникальность в базе по `(campaign_id, email)` остаётся последней защитой. При повторе запроса подтверждения импорт остаётся идемпотентным. Предпросмотр и импорт проходят через один серверный код нормализации и валидации, а сопоставление, выбор листа и данные файла относятся к одной версии предпросмотра.

## XLSX и ограничения безопасности

- Поддерживать только `.xlsx`; `.xls` сообщает, как пересохранить таблицу.
- Ограничивать размер файла и объём обработки до чтения книги; принимать только один выбранный лист.
- Не выполнять формулы и макросы. Макросы `.xlsm` не поддерживаются как формат импорта и не исполняются.
- Сохранять кириллицу, строки, телефоны и идентификаторы с ведущими нулями в том виде, в каком Excel показывает сохранённое значение.
- Ошибки повреждённого, пустого или неподдерживаемого файла показывать до импорта.

## Ошибки и проверка данных

- Нет назначения Email: подтверждение заблокировано, мастер остаётся доступен.
- Пустой или синтаксически неверный Email, дубликат в файле, существующий контакт кампании и пустые обязательные переменные показываются с номером исходной строки и причиной. Сообщение об ошибке не должно создавать впечатление, что приложение проверило существование почтового ящика.
- ФИО не разбивается автоматически. Пользователь назначает исходную колонку как «Полное имя» либо задаёт отдельные имя/фамилию.
- Строки с недопустимыми данными не приводят к частичному сохранению.
- Заголовки и содержимое считаются данными, а не инструкциями; импортированные значения отображаются безопасно и проходят существующую обработку контента.

## Проверка приёмки

1. CSV без заголовка `email` открывает мастер; «Почта» можно назначить Email, «Организация» — Компания, «Контактное лицо» — Полное имя, «Направление» — пользовательское поле. Колонка, назначенная «Не импортировать», не попадает в переменные.
2. Значения полей доступны в редакторе, подставляются в тему/письмо по соответствующим переменным и показывают пример значения.
3. Файл с двумя одинаковыми заголовками «Письмо 1» не теряет колонки; каждое значение можно назначить разным шагам или явно пропустить.
4. Явно назначенные колонки темы и «Письмо 1»/«Письмо 2» создают персонализированные шаги до 20; отсутствие колонок писем не блокирует импорт контактов.
5. Для `.xlsx` с несколькими листами импортируется только выбранный лист. CSV и XLSX с эквивалентными данными и назначениями дают одинаковые контакты, переменные и шаги.
6. При отсутствии Email подтверждение заблокировано. Неверные и повторные адреса, существующие контакты и пустые значения видны в предпросмотре с исходными строками.
7. Предпросмотр не меняет БД. Ошибка при окончательном импорте не оставляет частично импортированных лидов; повтор запроса не создаёт дублей.
8. Старый CSV с заголовком `email` продолжает импортироваться через мастер; существующие переменные и пользовательские письма сохраняют поведение.
9. Пустые/повреждённые книги, `.xls`, превышение лимита файла/строк и повторяющиеся заголовки обрабатываются явно и безопасно; пустой лист показывает приведённое выше уведомление.

## Вне объёма

- Внешняя проверка существования адреса и покупка её провайдера (#9).
- Обогащение контактов, автоматическое разбиение полного имени, назначение тегов, объединение нескольких листов и исполнение формул/макросов.
- Перезапись существующей цепочки без отдельного явного выбора пользователя.
